## 使用入口

1. 聊天输入区「图片」从照片选择；「文件」可选 PNG/JPEG/GIF。「表情」打开本会话角色的专属表情库。附件可单独发送、移除，点开可放大。
2. 角色详情 →「专属表情包」：从照片或文件导入，填写名称和含义，可编辑、替换文件或移除。替换保留编号，已发送消息保持原素材。聊天「表情」面板和「AI 与人格」也可进入管理。
3. 角色详情 →「AI 与人格」→「该角色的能力」：独立开启「允许 AI 发送专属表情」「允许角色了解和操作 App」，保存后生效。旧用户默认关闭这两项。
4. 角色操作修改前会显示具体内容，确认后执行；不确认、停止回复或确认超时则不执行。读取状态无需逐次确认，但需要该角色权限。

## 图片与表情的区别

- 普通图片是消息附件，不会自动进入表情库。
- 表情保存角色归属、名称、含义和原文件；AI 只能选择自己库里的真实 ID，每次回复最多一个。群聊各角色仍独立。
- PNG/JPEG 静态图和 GIF 都可使用；GIF 在聊天里按原帧延时播放，保留透明度和原文件，不用重新生成每帧。播放器按显示尺寸逐帧解码，减少动态效果时显示静态帧。
- 单文件最大 10 MB、边长最大 4096、GIF 最多 600 帧且最长 20 秒；每条最多 4 个附件，每角色最多 100 个表情。
- 从照片选择的 HEIC 等不兼容静态格式或超大照片会转为最长边 2048 的兼容图片，保留透明通道；已兼容图片原样保存，GIF 不经这条转换路径、不转成静态图。文件入口仍限 PNG/JPEG/GIF。
- 普通图片发给 DeepSeek 时使用最多 1280 边长的 JPEG 静态预览；本轮和所选历史合计最多携带最近 4 张图片。GIF 发给模型的是静态预览，不能声称理解了完整动画；未附原图的旧消息有明确说明。
- 接口使用现有 DeepSeek 配置。需要支持图片的模型；没有真实密钥的测试仅验证协议和界面，不代表已验证真实服务的识图质量。

## 角色可操作的范围

- `app_state`：当前陪伴、自己的动作/展示图、可选场景和自己的普通闹钟；不提供聊天记录、密钥或其他角色闹钟。
- `select_character`：选择自己作为主页角色；陪伴期间不切换。
- `start_companion` / `finish_companion`：开始或结束自己的陪伴，不覆盖或结束其他角色的陪伴。
- `set_scene` / `set_artwork`：设置场景或本角色展示图；不能改其他角色当前陪伴的场景。
- `set_actions`：设置本角色自动活动开关，按现有时间表轮换，**不声称立刻播放**。
- `create_alarm` / `cancel_alarm`：创建未来一年内的系统声音闹钟，或取消自己的普通闹钟；不能借此取消陪伴关联提醒。仍须系统授权。
- 请求提供 App 实际时间、设备时区和用户消息发送时间；状态工具返回最新时刻。相对提醒以原消息时刻为基准，确认执行时重新检查日期尚未过期。
- 通过官方 function tools 发起请求，严格校验工具名和参数，无任意 URL、脚本或外部 App 操作接口。一次回复最多 6 次接口往返、8 次工具调用。
- 写操作先保存操作意图，再确认并执行，保存结果；同一轮同角色同参数重试复用结果。执行结果未能落盘时保守停止，不盲目重复创建闹钟或重复启动陪伴。失败或取消后要改变同一项操作，请重新发一条消息。
- 思考模式工具往返需要的 `reasoning_content` 仅在当轮内存中回传，不显示、不写入聊天或备份。

## 存储、升级与备份

- 旧版文字聊天、配置和消息格式继续可读；新字段均可缺省。此处不增加长期记忆、摘要或跨会话记忆。
- 原媒体按 SHA256 命名，放在聊天历史旁的 `Media/` 目录，校验真实图片格式、文件大小和摘要。禁止把元数据当任意路径使用。
- 原文件本机保存并沿用首解锁后文件保护，目录排除系统备份，不写入源码或 Git。
- 新版 JSON 备份 v2 包括引用的图片、表情原文件、草稿附件及聊天配置；恢复前校验全部引用和摘要。仍支持旧版 v1 文字备份。
- 单份备份仍为 20 MB，含 base64 媒体。超限明确拒绝，不导出缺图备份；不包含 API 密钥、动作素材、闹钟或安装助手身份缓存。
- 移除库里的表情不会破坏已发送消息，历史保存表情快照及对应原文件。孤立原文件暂不自动清理，避免误删。
